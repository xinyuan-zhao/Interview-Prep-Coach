# 模拟面试评分与执行标准

开始或评分 Mock Interview 前阅读本参考。

## 目录

1. 开场设置
2. 面试官行为
3. 追问策略
4. 评分锚点
5. 结束报告
6. Coach Mode

## 1. 开场设置

从上下文判断或确认：

- 目标岗位和公司。
- 面试轮次与类型。
- 面试语言。
- 难度偏好。
- 主问题数量，默认 6–10 道。
- 标准 Interviewer Mode 或 Coach Mode。

已有简历/JD 信息时直接问第一题，不要重复设置。信息不足时，只索取能让问题与岗位相关的最少信息。

## 2. 面试官行为

- 每轮只问一个问题。
- 回答前不给提示或标准答案。
- 面试官回应保持简短、中性。
- 根据用户的答案继续，而不是照固定脚本。
- 允许停顿、不确定和不完美答案，保持真实感。
- 不制造细节，不替候选人完成故事。
- 结合岗位需要，在核心定位、行为题、简历深挖、风险题和职能题之间变化。

## 3. 追问策略

用追问验证可信度与深度：

- 你个人具体负责什么？
- 为什么选择这个方法？
- 当时还考虑过哪些方案？
- 最大障碍是什么？
- 谁不同意？你如何回应？
- 你做了什么取舍？
- 如何衡量成功？
- 实施后发生了什么？
- 如果重来一次，你会改变什么？

回答模糊时，每次只追一个缺失细节。出现矛盾时，用中性语气请用户澄清。

## 4. 评分锚点

每个维度 1–5 分，基于整场表现，不因单个回答直接定性。

| 维度 | 1 分 | 3 分 | 5 分 |
|---|---|---|---|
| 是否直接回答 | 大多跑题或回避 | 最终回答，但铺垫过长 | 直接、聚焦、完整 |
| 结构 | 难以跟随 | 基本清楚，偶有漂移 | 清楚、简洁、容易理解 |
| 个人贡献 | 责任模糊或夸大 | 部分个人行动清楚 | 决策和贡献非常具体 |
| 具体性/可信度 | 通用、无依据或矛盾 | 有部分细节，仍有缺口 | 具体、一致、可信 |
| 结果/影响 | 没有结果或暗示虚假影响 | 有结果但与行动连接弱 | 真实结果与价值清楚 |
| 岗位相关性 | 与核心需求关系弱 | 有可迁移性但间接 | 强力证明优先需求 |
| 自然表达 | 像背稿、术语过多或冗长 | 基本自然 | 简洁、自信、真实 |

介于锚点之间时使用 2 或 4 分。没有数字但有真实、清楚的定性结果时，不应因此扣分。

## 5. 结束报告

### 评分表

| 维度 | 得分 |
|---|---:|
| 是否直接回答问题 | /5 |
| 结构 | /5 |
| 个人贡献 | /5 |
| 具体性 / 可信度 | /5 |
| 结果 / 影响 | /5 |
| 与岗位相关性 | /5 |
| 自然表达 | /5 |

### Top 3 优势

引用用户在具体回答中的行为，不说空泛优点。

### Top 3 改进

明确说明要改变什么。不要只说“更自信”，要说“第一句先给结论，把背景缩短到两句，再展开个人决策”。

### 需要重练的问题

选择改进价值最高的 2–3 道题。

### 更好的答案结构

只能使用候选人已经提供的事实重组答案。尚未确认的信息必须留为待补充项，不得填空编造。

## 6. Coach Mode

每题后保持简短：

1. **面试官听到了什么：** 一句话总结。
2. **做得好的地方：** 最多两点。
3. **最大问题：** 最多两个。
4. **追问：** 继续面试。

用户没有要求时，不提供完整重写稿，保持面试节奏。
